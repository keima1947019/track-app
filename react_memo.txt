# 重複登録除外の仕組み
重複判定はゼッケン番号（bib）だけです。取り込み開始時に、登録済み選手のゼッケンを Set に入れます。TrackAndFieldApp.jsx:253
CSVの各行では、まずゼッケンと氏名が空なら必須項目不足としてスキップします。ゼッケンが Set にすでにあれば重複としてスキップし、なければ Set に追加して登録対象にします。そのため、同じCSV内でゼッケンが重複している場合も、先に現れた行だけが登録されます。
氏名や所属が同じでも、ゼッケンが異なれば重複扱いにはなりません。登録済みの選手を上書きせず、新規分だけ一覧に追加する

エントリ選手一覧に記載されているデータを使用してプログラム編成を作成する形にしてください。
添付したサンプルデータには男女、全部門、全種目において満遍なく選手が参加する形にして下さい。「小学3・4年」「小学5・6年」の部門は100m、1000mがあり、「中学」の部門は100m、200m、400m、800m、1500m、4*100mR、走り幅跳び、走り高跳びがあり、「一般」「壮年」の部門は100m、3000m、砲丸投げ、ジャベリックスローがあります。それに合わせてTrackAndFieldApp.jsxの内容修正をお願いします。TrackAndFieldApp.jsxは初期状態で選手データをブランク状態にしてください。
最初にはあったgoogle OAuth認証のログインが消えています。
許可ユーザーはgoogle auth platfoem側でPublishing statusをtestingにすることでtest usersを指定できるので、そこで制限します。
これまでに実装してくれたいろいろな機能がなくなっているようにみえます。
初期状態は選手一覧はブランクにして下さい。選手登録を一括で実施するためのcsvインポートボタンが欲しいです。
未ログイン時は選手一覧も見せないでください。選手一覧のカラムはゼッケン、氏名、所属団体、性別、種目、PB（個人ベスト記録）です。
エントリ選手一覧には部門のカラムが必要です。
プログラム編成・組割りにリレーも追加してください。リレーは1走～4走までがわかるようにしてください。
リレーを含めて全部の部門で男女ともに全ての種目に漫勉なくエントリーするようにサンプルデータを作成してください。1組あたり8名でレーン編成テストを行いたい。
選手一覧にリレーのオーダーに関するカラムがあるので、一括登録用csvにもそのカラムが必要では？
すみません。視認性が低下するのでリレー選手は別に管理する形で良いのでは？
リレーに関しては個人ではなく団体が主体となって申し込み、複数チームでエントリーする団体があるので、それを考慮してください。
1500m、3000m、フィールド種目はタイム決勝なので1組のみの編成にしてください。フィールド種目については5回まで記録を残します。
競技結果入力について、トラック競技の場合は、まず着順にレーン番号を入力していくため、レーン番号を入力すると自動的にゼッケン、氏名が表示される仕組みにしてください。
リレー登録csvには選手名とオーダー番号（走順）も含めること。選手登録した時点でプログラム編成、組割りも自動的に生成すること。
テスト用にランダムで競技結果を入力するボタンをつけてください
長距離以外の種目も状況によってはタイム決勝になることがあるため、組毎の結果以外にタイム決勝の結果を示してください。

# 仕組み
「1組あたりの上限人数」（デフォルト8名）を指定し、ワンクリックで持ち記録(PB)順に1組・2組へ組割り。
セパレートコース種目（100m, 200m, 400m等）では優先レーン順（4 → 5 → 3 → 6 → 2 → 7 → 1 → 8）を自動割り当て。
フィールド種目や長距離種目の場合は試技順/スタート順を自動割り当て。
陸上競技公式ルールに準拠したレーン配置（Center-Out Seeding）機能
1組あたりのレーン数（4 / 6 / 8 レーン）を選択可能にしました。
PB（自己記録）が良い選手を走りにくい端レーンではなく、トラック中央レーン（例: 8レーンなら4, 5レーン）に優先配置する標準シーディング配置ロジックを実装しました。
管理画面は　http://localhost:8081/?admin=1
